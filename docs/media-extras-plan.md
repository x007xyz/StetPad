## P5 必须先补的缺口

这几项不是新功能，是现在已经能踩到的问题，建议排在所有新功能之前。

### 5.1 云同步不带文件（高）— 已完成 2026-11-16
- 实现：`sync.ts` 的同步桥扫描文档引用的 `/files/<id>`，缺哪边补哪边（本地有、云端没有就上传，反之下载），文件编号两边一致；新增按编号上传的 `PUT /api/docs/:id/assets/:assetId`（重复上传直接返回成功）。同步建立时会补齐以前遗漏的文件；失败的文件 30 秒后重试。测试：`server.test.ts` 的云同步用例覆盖了双向传输。
- 尚未做：大视频断点续传（中途断开会整段重传）。
- 原问题：`sync.ts` 只同步 Yjs 文档，不同步 `/files/<id>`。桌面端开了云同步的文档，图片、视频、draw.io 预览在云端全部是坏链接。
- 做法：同步时扫描文档里引用的 `/files/<id>`，云端缺的就上传（复用 `POST /docs/:id/assets` 的原始流上传）；云端拉下来的文档同理反向下载。资产 id 保持不变，文档内容不用改写。
- 文件：`packages/server/src/sync.ts`、`db.ts`（记录已同步的资产）。
- 验收：本地插图 → 开同步 → 云端网页打开能看到图；视频走分块，断网重连可续传。

### 5.2 文档包导出不含文件（高）— 已完成 2026-11-16
- 实现：导出菜单“文档包（含图片、视频和全部版本）”生成 `.stetpad`（zip：`document.json` + `assets/<id>`），保存完整 CRDT 状态（含未处理的修订和评论）与版本历史；有视频时询问是否一起导出。首页拖入或“导入文件”选择 `.stetpad` 即可导入为新文档；导入时文件换新编号并改写文档和各版本里的引用，删除原文档不影响副本。旧的 `.stetpad.json` 也能导入（只有内容和版本）。导入和导出都流式处理；`document.json` 上限 256MB，整个包上限 4GB。代码：`packages/server/src/package.ts`，测试：`package.test.ts`。
- 尚未做：导入时因类型或大小不合格被丢弃的文件，目前不在结果里告知用户。
- 原问题：`format=json` 的“文档包”号称用于备份和迁移，但不含图片和视频，换机器导入后全是坏链接。
- 做法：文档包改成 zip：`document.json` + `assets/<id>`；导入时先写资产再建文档。视频大时提示体积，允许选择“不含视频”。
- 验收：导出 → 在另一个数据目录导入 → 所有媒体可显示、可播放。

### 5.3 孤儿文件清理（中）— 已完成 2026-11-16
- 实现：`packages/server/src/gc.ts`。启动 5 分钟后跑一次、之后每 24 小时一次，删除创建超过 7 天（`AIW_ASSET_GRACE_DAYS` 可改）且没有任何文档引用的文件；引用范围是所有文档的当前内容、未合并的更新、全部版本，以及正在内存里编辑、还没写入数据库的文档。删除文档时立即清理它的文件，但别的文档还在用的保留，10 分钟内新建或复用的也留给定期清理（防止浏览器还没发到服务器的引用被误删）。同一用户重复上传相同文件时复用已有文件（按 SHA-256，不跨用户）。测试：`gc.test.ts`。
- 原问题：删除图片块、拒绝 AI 生成图片的建议、反复保存 draw.io，都会留下不再被引用的文件；只有删除整篇文档时才清理。
- 做法：定期任务：资产创建超过 7 天、且当前内容和所有版本快照都不再引用，则删除。按内容哈希去重（同一张图粘贴多次只存一份）。
- 验收：测试覆盖“版本里还引用的不删”“拒绝的建议里的图会删”。

## 已知限制的处理（2026-11-17）

| 原限制 | 处理 | 验证 |
|---|---|---|
| 嵌入视频要先选中块才能操作播放器 | 遮罩上加播放按钮：点一下同时选中块并开始播放（上传的视频调用 `play()`，嵌入的播放器地址加 `autoplay=1`）。`apps/web/src/editor/video.ts` | 浏览器：一次点击后块被选中、遮罩消失、地址带 `autoplay=1`；平台是否真的自动播放未逐个验证 |
| Mermaid 只在"按修改稿导出"时带图 | 网页导出时浏览器按所选版本（修改稿或原文）在浅色主题下现画；服务端按"文档 + 源码"缓存 SVG（`<dataDir>/renders/`，删除文档时清掉），编辑器显示过的图和以前导出过的图，GET 接口导出时也能带上。`render.ts` 的 `RenderCache`，新接口 `GET /docs/:id/export/diagrams`、`PUT /docs/:id/renders` | `mermaid-export.test.ts`；浏览器：Word 原文导出带上了图，GET 导出 HTML 带 SVG |
| Imagen 选 3:2 时按 16:9 生成 | 按 4:3 / 3:4 生成后居中裁成 3:2 / 2:3（`cropToRatio`） | `images.test.ts`；没有用真实 Google 密钥跑过 |
| 修订模式下公式里待删除的字符仍参与渲染 | 公式按修改稿渲染，跳过待删除的字符（`tracked.ts` 的 `hiddenRanges`） | 浏览器：删除公式最后一个字符后，渲染结果不含该字符 |
| AI 读文档时公式不带 `$` | AI 读到的段落里行内公式写作 `$…$`，字面美元符号写作 `\$`；AI 写回时还原，未改动的公式不产生修订，新写的公式自动加上公式格式。未转义的价格（`$5 和 $6`）按普通文字处理 | `inline-math-notation.test.ts` |
| 断点续传的状态在内存里 | 每个上传的状态写在临时文件旁的 `<id>.json`，启动时读回并与临时文件对齐 | `uploads.test.ts` |
| HTML 导出不带字幕轨 | 有字幕时导出 `<track kind="subtitles">` | `video.test.ts` |

顺带修复：从 Markdown 等文件导入时，行内公式的格式会在建文档时被丢掉（`sanitizeBlocks` 的允许列表里没有 `math`）。

## 仍然存在的限制

- 从没在编辑器里显示过、也没从网页导出过的 Mermaid 图，GET 接口导出时仍是源码。
- 浏览器只在约 30 秒内自动重试上传；刷新页面后需要重新上传。
- 模型能力（文字、识图、生图、改图、转写）默认勾选文字和识图；"识图模型"选"自动"时用默认模型（它勾选了识图的话），否则用第一个勾选了识图的模型。
